## ۰. محدودیت اساسی این ممیزی (پیش از هر چیز بخوانید)

محیط اجرایی این ممیزی (کانتینر ابری Claude Code) از طریق یک پراکسی خروجی با **فهرست سفید دامنه** به اینترنت متصل است. دامنه `sorud.info` (و همه ابزارهای شخص ثالثِ اندازه‌گیری) در این فهرست نبودند. شواهد دقیق:

| تلاش | نتیجه دقیق |
|---|---|
| `curl https://sorud.info` | `curl: (56) CONNECT tunnel failed, response 403` |
| `curl http://sorud.info` | `HTTP/1.1 403 Forbidden` با هدر `x-deny-reason: host_not_allowed` و بدنه `Host not in allowlist: sorud.info. Add this host to your network egress settings to allow access.` |
| `curl https://www.sorud.info` | همان خطای 403 در CONNECT |
| ابزار WebFetch روی `https://sorud.info/`، `/robots.txt`، `/sitemap.xml` | `EGRESS_BLOCKED: Access to sorud.info is blocked by the network egress proxy.` |
| Wayback Machine (`web.archive.org`) | `Claude Code is unable to fetch from web.archive.org` |
| PageSpeed Insights API (`pagespeedonline.googleapis.com`) | `HTTP 429` — `Quota exceeded ... quota_limit_value: "0"` (سهمیه صفر) |
| crt.sh، ssllabs، securityheaders.com، builtwith، similarweb، hypestat، rdap.org، ripe RDAP، dns.google | همگی `403` در CONNECT (خارج از فهرست سفید) |
| `openssl s_client -connect 88.153.216.110:443` | گواهی برگشتی توسط `Egress Gateway SDS Issuing CA (production)` (Anthropic) امضا شده بود، یعنی پراکسی TLS را قطع می‌کند و گواهی واقعی سایت قابل مشاهده نیست |
| رقبا (`prosody.ir`، `ganjoor.net`، `blog.ganjoor.net`) | `EGRESS_BLOCKED` |

**نتیجه:** هیچ صفحه‌ای از sorud.info در این ممیزی مستقیماً باز نشد. تنها کانال‌های کارکرد این‌ها بودند:

1. **تفکیک DNS محلی** (`getent hosts`، `socket.getaddrinfo`، `socket.gethostbyaddr`) — کار کرد و شواهد زیرساختی معتبری داد.
2. **جستجوی وب** (WebSearch) — عنوان ایندکس‌شده صفحه اصلی، معرفی گنجور، و اطلاعات رقبا از این مسیر آمد.

بنابراین در این گزارش، هر محوری که به مشاهده‌ی مستقیم صفحه نیاز دارد، صریحاً با عبارت **«قابل اندازه‌گیری نبود»** علامت خورده است. هیچ عدد سرعت، هیچ متن HTML و هیچ هدر HTTP از سایت هدف در این گزارش «حدس» زده نشده است. برای تکمیل ممیزی، لازم است دامنه‌های فهرست‌شده در پیوست ب به تنظیمات network egress محیط اضافه شوند و ممیزی دوباره اجرا شود.

## ۱. خلاصه مدیریتی

**sorud.info چیست؟** بر اساس معرفی رسمی در وبلاگ گنجور (`https://blog.ganjoor.net/1396/09/08/sorud-info/`، ۸ آذر ۱۳۹۶) و عنوان ایندکس‌شده صفحه اصلی («سرود: بررسیِ وزنِ شعر - عروض»)، «سرود» یک **ابزار تک‌منظوره‌ی آنلاین برای تشخیص وزن عروضی شعر فارسی** است. کاربر متن شعر را وارد می‌کند، دکمه «بررسی» را می‌زند و سایت ساختار وزن مصراع‌ها را با رنگ‌بندی هجاهای کوتاه/بلند نشان می‌دهد و یک نمونه‌ی آشنا از همان وزن می‌آورد. طراح آن «دکتر نوید فاضل» (پژوهشگر ادبیات و دستور زبان فارسی) معرفی شده است. ادعای پوشش: ۷۱ وزن و ۵۲۱۲ ساختار آهنگی.

**مخاطب هدف (استنباط از منابع ثانویه):** شاعران نوآموز، دانش‌آموزان و دانشجویان ادبیات، مدرسان عروض، و پروژه‌های داده‌ای مثل گنجور که وزن‌یابی ماشینی می‌خواهند.

**مدل درآمدی:** هیچ نشانه‌ای از تبلیغ، اشتراک یا فروش در منابع در دسترس دیده نشد. **قابل اندازه‌گیری نبود.** رقیب مستقیم (prosody.ir) صفحه «حمایت مالی» دارد؛ برای سرود چنین چیزی در ایندکس دیده نشد.

**مهم‌ترین یافته‌های مبتنی بر شواهد (بدون دسترسی به خود صفحه):**

1. **میزبانی روی اتصال اینترنت خانگی/مصرفی در آلمان (بحرانی).** رکورد A دامنه به `88.153.216.110` اشاره می‌کند که PTR آن `ip-088-153-216-110.um27.pools.vodafone-ip.de` است (استخر IP پویای Vodafone آلمان). رکورد AAAA به `2003:c8:4fff:217e:464e:6dff:feae:c839` با PTR `p200300c84fff217e464e6dfffeaec839.dip0.t-ipconnect.de` اشاره می‌کند (استخر IP پویای Deutsche Telekom). یعنی سایت روی سرور ابری/هاست حرفه‌ای یا CDN نیست، بلکه پشت یک خط اینترنت مشترک خانگی است.
2. **سابقه‌ی قطعی و تغییر IP (بالا).** در نظرات همان پست گنجور، کاربران خطای «دسترسی به این صفحه امکان‌پذیر نیست» را گزارش کرده‌اند و مدیر گنجور آدرس موقت `http://95.223.207.205/sorud/` را داده است. PTR این IP نیز `ip-095-223-207-205.um35.pools.vodafone-ip.de` است. تغییر IP از `95.223.207.205` به `88.153.216.110` مؤید IP پویا و ریسک دائمی در دسترس‌پذیری است.
3. **دوگانگی ISP در IPv4 و IPv6 (متوسط).** IPv4 روی Vodafone و IPv6 روی Telekom است. کاربرانی که IPv6 دارند به یک مسیر و بقیه به مسیر دیگری می‌روند؛ اگر یکی از دو خط قطع شود، بخشی از کاربران سایت را «پایین» می‌بینند.
4. **پوشش ایندکس تقریباً تک‌صفحه‌ای و با پروتکل HTTP (بالا).** در همه‌ی جستجوها تنها یک URL از این دامنه ظاهر شد: `http://www.sorud.info/`. هیچ URL دیگری (راهنما، درباره، فهرست اوزان) ایندکس نشده و نسخه‌ی ایندکس‌شده **http** و **www** است. وضعیت HTTPS و canonical قابل تأیید نبود.
5. **شریک اصلی (گنجور) به‌طور عمومی خطای موتور را اعلام می‌کند (متوسط).** صفحات آمار اوزان گنجور (مثلاً `https://ganjoor.net/attar/vazn/`) می‌نویسند: «وزن‌یابی ماشینی نیز که جدیداً با استفاده از امکانات تارنمای سرود اضافه شده بعضاً خطا دارد.» این هم بزرگ‌ترین بک‌لینک/اعتبار سرود است و هم یک سلب‌مسئولیت عمومی درباره‌ی دقت آن.
6. **رقبا شاخص دقت و روایت فنی منتشر می‌کنند، سرود نه (متوسط).** وزن‌یاب نوسخن (`vaznyab.nosokhan.com`) دقت ۹۷.۸٪ روی ۶۰ هزار بیت در ۵۰ وزن را ادعا می‌کند؛ وبگاه عروض (`prosody.ir`) مقاله‌ی کنفرانسی و صفحه داده‌ها دارد. برای سرود هیچ سند دقت یا مقاله‌ای در ایندکس پیدا نشد.
7. **رکود محتوایی/ارتباطی (متوسط).** آخرین پوشش شخص ثالث قابل یافتن، آذر ۱۳۹۶ است. هیچ خبر، به‌روزرسانی، شبکه اجتماعی یا وبلاگ متعلق به سرود در نتایج جستجو دیده نشد.

**نتیجه‌ی کلی:** بر اساس شواهد زیرساختی و ایندکسی، sorud.info یک ابزار ارزشمند و منحصربه‌فرد (به گواهی گنجور) است که روی زیرساختی شکننده و بدون ردپای سئو/محتوایی اجرا می‌شود. محورهای عملکرد، UX، دسترس‌پذیری، هدرهای امنیتی و تحلیل، **تا زمان باز شدن دسترسی شبکه قابل اندازه‌گیری نبودند** و باید در دور دوم ممیزی تکمیل شوند.

### پیوست ب) ابزارها و معیارها

**ابزارهای اجراشده:** `curl 8.x`، `openssl s_client`، `getent`، Python `socket` (getaddrinfo/gethostbyaddr)، WebFetch، WebSearch، PageSpeed Insights API v5 (ناموفق).

**ابزارهایی که قرار بود اجرا شوند و نشدند (به دلیل مسدودی):** Lighthouse/PSI (موبایل و دسکتاپ)، رندر Chromium/Playwright برای CLS/INP و اسکرین‌شات‌های ریسپانسیو، بررسی هدرها با curl -I، اعتبارسنجی HTML (validator.w3.org)، crt.sh برای گواهی، securityheaders.com، robots/sitemap parse، axe-core برای WCAG.

**معیارهای نمره‌دهی:** هر محور فقط بر مبنای شواهد مستقیم نمره گرفته است؛ محور بدون شاهد «—» است. شدت مشکلات: بحرانی = سایت را از دسترس خارج می‌کند یا ریسک امنیتی مستقیم دارد؛ بالا = بر جذب کاربر یا اعتماد اثر مستقیم دارد؛ متوسط = بر رقابت‌پذیری اثر دارد؛ پایین = بهبود کیفی.

**پیش‌نیاز تکمیل ممیزی در دور دوم:** افزودن این میزبان‌ها به فهرست سفید network egress محیط:
